Part 1: Fun with Filters

Part 1.1: Convolutions from Scratch!

Both 2D convolution implementations flip the filter, use zero-padding for "same" padding, and, at each position, sums the elementwise products of the filter with the underlying image patch. There is a four-loop version and a two-loop version that vectorizes the filter application with a single np.sum over a sliced patch.

Four-loop implementation

def convolution_four(img, filter):
      h, w = img.shape
      fh, fw = filter.shape
    
      pad_y = (fh-1)//2
      pad_x = (fw-1)//2
    
      pad = np.pad(img, ((pad_y, pad_y), (pad_x, pad_x)), mode="constant", constant_values=0)
    
      kernel_flipped = filter[::-1, ::-1]
    
      out = np.zeros((h,w))
    
      for hi in range(h):
        for wi in range(w):
          for fhi in range(fh):
            for fwi in range(fw):
              out[hi, wi] += pad[hi+fhi, wi+fwi] * kernel_flipped[fhi, fwi]
    
      return out

Two-loop implementation

def convolution_two(img, filter):
      h, w = img.shape
      fh, fw = filter.shape
    
      pad_y = (fh-1)//2
      pad_x = (fw-1)//2
    
      pad = np.pad(img, ((pad_y, pad_y), (pad_x, pad_x)), mode="constant", constant_values=0)
    
      kernel_flipped = filter[::-1, ::-1]
    
      out = np.zeros((h,w))
    
      for hi in range(h):
        for wi in range(w):
            patch = pad[hi:hi+fh, wi:wi+fw]
            out[hi, wi] = np.sum(patch * kernel_flipped)
    
      return out

I verified both against scipy.signal.convolve2d(img, filter, mode='same') using np.allclose, with the 9x9 box filter and the finite difference operator Dx, and it returned True in both cases.

I noticed the two-loop version was actually taking longer on the finite difference operators and decided to figure out what was going on. The two-loop version's runtime is nearly constant with filter size, since the inner loop is vectorized and most of the time is taken by the outer pixel loop. The four-loop version scales with filter size, since every filter weight is visited by an explicit Python loop. scipy.signal.convolve2d outperforms both by a lot regardless of filter size.

Boundary handling

All versions zero-pad the image by (filter_size - 1) / 2 on each side so the filter can be centered on every pixel, including edges, keeping the output the same size as the input.

Part 1.2: Finite Difference Operator

Convolving the cameraman image with the finite difference operators Dx = [[1, 0, -1]] and Dy = Dx.T gives the partial derivatives in x and y. Combining them into the gradient magnitude, mag = sqrt(dx² + dy²), gives a single per-pixel measure of edge strength regardless of direction. When I binarized mag at a threshold of my choice, it produced an edge image.

I tested thresholds of 0.1, 0.15, 0.2, and 0.3. Lower thresholds (0.1, 0.15) captured more edges but also let through noise in like the grass in the foreground. Higher thresholds (0.3) removed almost all the noise but started breaking up the actual edges. I decided on threshold = 0.2 because it keeps the cameraman's silhouette, face, camera, and tripod as continuous, connected edges, but there is some residual speckling in the grass.

Part 2: Fun with Frequencies!

Part 2.1: Image "Sharpening"

For sharpening, I begin by using a gaussian filter to get a blurred version of the original image. Subtracting that blurred version from the original isolates the high frequencies(ie. edges and fine detail)that the blur removed. Adding some extra weight of those high frequencies back onto the original makes detail more prominent, sharpening the image. Algebraically,

sharpened = img + α(img − blurred) = img ∗ [(1+α)e − αG]

where e is the unit impulse filter and G is the Gaussian. Since blurring is also done via convolution, both steps can be combined into one convolution. I verified that both approaches return the same thing, since (np.allclose returns True).

Part 2.2: Hybrid Images

A hybrid image combines the high frequencies of one image with the low frequencies of another. Up close, the high-frequency image is clearer and from a distance the low-frequency image is clearer. The high-pass filter is computed as the original image minus a Gaussian-blurred version of itself; the low-pass filter is just the Gaussian blur. The two are then added together. Each image's cutoff is controlled by its own Gaussian's sigma.

Part 2.4: Multiresolution Blending (a.k.a. the oraple!)

At each level, I take image A's Laplacian band and weigh it by that level's blurred mask, then take image B's band and weigh it by one minus the mask, and add the two together. Summing up all the levels collapses everything back into the final blend. Since the mask gets blurrier the deeper you go, low frequencies end up blended over a wide, soft seam while high frequencies stay blended over a narrow, sharp one.

What I Learned

I was surpirsed by how much you can do with such simple operations. Everything from sharpening to edge detection to hybrid images were rooted in convolving an image with a Gaussian over and over in different combinations. There's a lot you can do by just blurring, subtracting, and recombining at different scales. It was surprising to see how far something so simple can go. For example, knowing what aspects of an image a blur removes is enough knowledge to sharpen an image or fuse two faces into one.
